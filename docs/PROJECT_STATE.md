- **🐞 VIDEO EDITOR EXPORT CRASH AFTER TRIM/SPLIT — ✅ FIXED v1.105.1, E2E-verified (2026-07-10).** Exporting after moving the trim start/end or splicing (removing a middle piece) failed with `timestamp must be a non-negative number` (confirmed by Joey's error screenshot). **Root cause:** MediaBunny's `VideoSampleSink.samples(start,end)` yields a LEADING frame whose timestamp is ≤ the cut point (the frame visible at the cut). `export-video.ts` mapped it with `outCursor + (sample.timestamp - range.start)`, which goes **negative** for a trimmed start (`CanvasSource.add` rejects negative timestamps) and **backwards** at a split boundary (WebCodecs needs monotonic timestamps). Worked only when a cut landed exactly on a frame. **Fix:** new pure `mapOutputTimestamp()` clamps the in-range offset to ≥0 and forces strictly-increasing output (`MIN_TS_STEP`); the video loop tracks `lastOutTs`. Unit test `output-timestamp.test.ts` (negative clamp, monotonic split boundary, collision guard). **E2E-verified in real Chromium** (ffmpeg fixture): trim-start export ✅ and split+remove-middle export ✅ both succeed, 0 console errors (both previously threw). Touched: `src/lib/video-editor/export-video.ts` (+`output-timestamp.test.ts`). Audio leading-buffer overhang (minor A/V drift, non-crashing) noted as a possible follow-up — NOT bundled.
