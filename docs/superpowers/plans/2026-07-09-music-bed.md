## Want
Add a **background music track** to an exported marketing video, at a **controllable low volume** so
it sits under the live seller's voice (a "music bed"), not overpowering it.

## Context / why it's a clean fit
The intro/outro feature (SHIPPED v1.103.0, see [[project_video_intro_outro]]) already built the exact
infrastructure this needs:
- **Asset library:** `video_assets` table (id, name, kind, file_url, …) + public `video-assets` bucket
  + service `src/services/video-assets.ts` + hook `src/hooks/use-video-assets.ts`. `kind` is currently
  CHECK IN ('intro','outro').
- **Export audio mixing:** `src/lib/video-editor/export-video.ts` → `exportEditedVideo` already builds a
  single **master AudioBuffer** sized to the whole video timeline (`buildMasterAudio`), resampling each
  segment's audio to 48k. The music bed just **mixes into that master buffer** at reduced gain.
- **Editor controls:** `src/components/video-editor/intro-outro-controls.tsx` (Switch + asset Select +
  Manage-clips dialog) is the pattern to mirror; wired in `video-editor.tsx`.

## Build steps

### 1. DB — allow `kind='music'`
Migration (e.g. `20260709030000_video_assets_music_kind.sql`): drop + recreate the `video_assets_kind_check`
constraint to `CHECK (kind IN ('intro','outro','music'))`. Reuse the same `video-assets` bucket (music
files go under a `music/` prefix, same as intro/outro folders). No new table/bucket needed.

### 2. Service / hook — widen the type + accept audio
`src/services/video-assets.ts`: widen `VideoAsset.kind` + `createVideoAsset` input kind to
`'intro' | 'outro' | 'music'`. Nothing else changes (path already `${kind}/${uuid}.${ext}`). The manager
`<input accept>` must allow `audio/*` for the music kind; preview music with `<audio controls>` instead of
`<video>` (branch on kind).

### 3. Editor UI — Music control
Add a **Music** section (either extend `intro-outro-controls.tsx` or a sibling `music-controls.tsx`):
- On/off **Switch** + a **Select** of `kind='music'` assets (disabled when none, "add one →" hint).
- A **volume slider** (`src/components/ui/slider.tsx` if it exists, else a range input) 0–100%, **default 15**.
- The Manage-clips dialog gains **Music** as a third `kind` option in its Type select (and audio preview).
State in `video-editor.tsx`: `music: { enabled: boolean; id: string | null; volume: number }`.

### 4. Export — mix the music bed
`exportEditedVideo` gains `music?: { blob: Blob; volume: number } | null`. In `buildMasterAudio` (after the
voice/intro/outro master is assembled, length = total video duration):
- Decode the music blob → AudioBuffer; resample to 48k (`resample()` helper already there).
- **Loop** it to fill the full timeline if shorter; **trim** if longer.
- Apply **gain = volume/100** (so 15 → 0.15) and **mix** (add) into every channel of the master buffer,
  **clamping** each sample to [-1, 1] to avoid clipping.
- Music spans the ENTIRE output (intro → recording → outro) as a continuous bed.
Note: if a video has NO other audio (no mic + silent bumpers) but music is on, `buildMasterAudio` must
still create a master buffer (today it returns null when no segment has audio — add "or music present").
`video-editor.tsx` `runExport`: if `music.enabled` + id, `fetchAssetBlob(url)` → pass `{ blob, volume }`.

### 5. Verify (real Chromium via Playwright, like intro/outro)
- Export a recording (voice tone) + music track (different tone) at 15% volume. Decode the output audio and
  confirm BOTH frequencies are present (FFT or energy check), voice clearly louder than music, duration
  correct. Backend: create/list/delete a `kind='music'` asset round-trips under RLS.
- tsc + eslint + prod build green.

### 6. Ship
Bump version, update PROJECT_STATE + [[project_video_intro_outro]] / a new [[project_video_music_bed]]
memory, commit + push (`push-to-main` flow → `git push origin HEAD:main`, main == origin/main).
